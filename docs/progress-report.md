## نگاه کلان — کجای نقشه‌ایم (قانون ۳)

**پیجا چیست؟** یک «سیستم‌عامل کسب‌وکار» برای واسطه‌ها و فروشندگان اینستاگرام در عصر «تجارت عامل‌محور»
(Agentic Commerce — یعنی دستیارهای هوش مصنوعی به‌جای انسان‌ها خرید و فروش را هماهنگ می‌کنند).
تمرکز فروش: خدمات به فروشندگان (نه خریداران). نیچ آغازین: **لوازم آرایشی بهداشتی** 🧴

**مسیر کلی و جایگاه امروز:**

```
[✅] ۱. تحقیق بازار و استراتژی (۲ سند مصوب)
[✅] ۲. تسلط کامل به زیرساخت BoxAPI (سه خط محصولی + کشف‌های عملی)
[✅] ۳. طراحی فنی فاز ۱ (سند نقشه‌ی اجرا)
[✅] ۴. پیاده‌سازی «ستون فقرات داده» (کد + ۳۴ تست + CI سبز ×۲)
[✅] ۵. اثبات زنده با داده‌ی واقعی (کرال بازار + کاتالوگ واقعی)
[👈] ۶. استقرار روی هاست شما + حلقه‌ی رسمی وب‌هوک   ← اینجا هستیم
[ ] ۷. ارزیابی «عدد سرنوشت» (gold-100) و رسیدن به گیت‌های موفقیت
[ ] ۸. دموی فروش + مقیاس‌گیری
```

## بخش ۱ — چه کارهایی انجام شد (گزارش کامل، به زبان ساده)

### گام ۱ — تحقیق و استراتژی ✅
- **پژوهش بازار:** ۴۴ میلیون کاربر اینستاگرام ایران، ~۴۱۵ هزار فروشگاه، گردش مالی ~۱۵۰ هزار میلیارد تومان.
- **سند اول (Blueprint):** نقشه‌ی اولیه‌ی تجارت عامل‌محور برای بازار ایران.
- **سند دوم (FINAL-PROPOSAL — سند بالادستی):** معماری ۷ لایه‌ای «رستا»، فلسفه‌ی agent-native،
  مدل کسب‌وکار (اشتراک ۵۹۰ هزار تا ۴.۹ میلیون تومانی)، نقشه‌ی راه A0–A4 و گیت‌های F0–F4.

### گام ۲ — تسلط کامل به BoxAPI («از حفظ» ✅)
سه خط محصولی این سرویس را ریزبه‌ریز خواندیم و سپس **با پروب زنده تأیید کردیم**:

| خط محصول | چیست | برای چه |
|---|---|---|
| ① Official DM/Comment API | دسترسی رسمی متا (بدون ریسک بن) | حلقه‌ی فروش: دایرکت، کامنت، کارت محصول |
| ② Instagram Data API | داده‌ی عمومی پیج‌ها (کرال) | ایندکس بازار، استخراج کاتالوگ رقبا |
| ③ AI API | مدل‌های هوش مصنوعی | استخراج از تصویر (VLM) |

**کشف‌های طلایی از پروب واقعی:**
- میزبان واقعی خط ① سایت `api.sendbox.chat` است (نه خود boxapi.ir).
- اکشن‌ها **async** هستند: درخواست می‌دهید → «۲۰۲ پذیرفته شد» → نتیجه از **وب‌هوک** می‌آید.
- `GET /service/accounts` فهرست پیج‌های متصل را می‌دهد → صفحه‌ی تست شما: **@mmohebbi111**.
- **`is_echo` را روشن کردیم** ✅ — یعنی پیام‌های خود فروشنده هم به سیستم برمی‌گردد
  («قیمتی که فروشنده در چت می‌گوید = قیمت نهایی» — سیگنال طلایی!).

### گام ۳ — طراحی فنی فاز ۱ (سند phase-1-plan) ✅
«ستون فقرات داده»: موتوری که از دل محتوای اینستاگرام (کپشن/تصویر/کامنت)، **کاتالوگ ساخت‌یافته** بیرون می‌کشد:
محصول، ویژگی، قیمت — هرکدام با «مدرک» (Evidence) و «سطح اطمینان» (confidence).

### گام ۴ — پیاده‌سازی کد (مخزن peyja-project) ✅
**معماری — به زبان ساده:**

| لایه | کار | مثال ملموس |
|---|---|---|
| **پارسر قیمت فارسی** | قیمت‌های شکل ایرانی را می‌فهمد | «۴/۸۰» = ۴٬۸۰۰٬۰۰۰ تومان · «۴۸۰» = ۴۸۰ هزار · «توافقی» = قیمت در دایرکت |
| **موتور استخراج** | کپشن/تصویر → محصول + قیمت | regex سریگ و رایگان ← فقط برای موارد مبهم، هوش مصنوعی (VLM) |
| **Evidence** | هر قیمت «مدرک» دارد | از کجا آمد؟ چقدر مطمئنیم؟ «استخراج‌شده ≠ تأییدشده» |
| **بازه‌های اطمینان** | تصمیم خودکار/انسانی | ≥۰.۷ ذخیره خودکار · ۰.۴–۰.۷ صف تأیید انسان · <۰.۴ رد |
| **آرشیو رسانه** | دانلود فوری فایل‌ها | URL اینستاگرام منقضی می‌شود؛ ما با sha256 نگه می‌داریم |
| **کرالر بودجه‌دار** | مصرف کنترل‌شده | سقف درخواست + ادامه از همان‌جا که ماند (resume) |
| **وب‌هوک امن** | دریافت رویدادها | HMAC-SHA256 + جلوگیری از replay + حذف تکراری |
| **تاریخچه قیمت** | دارایی اطلاعاتی | «هشدار افت قیمت رقیب» — قابل فروش به فروشنده! |

**استاندارد کد (قانون ۱ — قله‌ی تکنولوژی):**
- پژوهش روز دنیا اعمال شد: Structured Outputs با «مسیر فرار» (مدل هرگز حدس نمی‌زند)،
  اعتبارسنجی Pydantic، retry با بازخورد خطا، temperature=0 [منابع: ۵ مقاله‌ی ۲۰۲۶].
- ابزار استاندارد ۲۰۲۶: `uv` + `Ruff` + `mypy` + ماتریس تست پایتون ۳.۱۱–۳.۱۳.
- **۳۴ تست** (پارسر، امنیت وب‌هوک، schema، آرشیو رسانه، تاریخچه قیمت) — همه سبز.
- **GitHub Actions:** هر push → بررسی خودکار؛ **۲ بار اجرا → ۲ بار SUCCESS** (قانون ۲).
