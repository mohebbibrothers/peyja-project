# پروتکلِ ارزیابی (قانون ۵) — چگونه نمره می‌دهیم تا بیش‌برازش نکنیم

## ۱. سطوحِ داده

| سطح | چیست | برای چه | قاعده |
|---|---|---|---|
| `dev` | نمونه‌هایی که موتور روی‌شان tuning شده (بچ ۱ = ۶۴ نمونه) | توسعه + قفلِ رگرسیون | نمره‌ی dev «خوش‌بینانه» است؛ فقط برای جلوگیری از پسرفت |
| `test` (holdout) | نمونه‌های دست‌نخورده (بچ ۲ به بعد — اکانت‌های جدید) | **عددِ رسمی** | هرگز در tuning دیده نمی‌شود |
| `adversarial` | پرتگاه‌های دست‌ساز (۲۸ مورد) | مقاومتِ قاعده‌ها | باید همیشه سبز بماند؛ تغییرِ قاعده باید آن‌ها را نشکند |
| `synthetic` | ۴ نمونه‌ی پوششِ فرمِ سختِ قیمت | پوششِ شکلِ نوشتاری | جدا گزارش می‌شود |

**اعترافِ صادقانه:** بچ ۱ (۶۴ نمونه) پیش از این پروتکل ساخته شده و قاعده‌ها
روی‌شان تنظیم شده‌اند؛ پس `dev`‌اند، نه تست. نمره‌ی ۱۰۰٪/۹۵٪ فعلی «عددِ dev»
است. اولین holdoutِ واقعی = اولین کرالِ تازه پس از تمدیدِ Data API.

## ۲. بهداشتِ تست (Test Hygiene)
1. نمونه‌ی test **هرگز** در هیچ تصمیمِ قاعده/lexicon/آستانه‌ای دیده نمی‌شود.
2. اگر تحلیلِ خطای test → تغییرِ قاعده شد: آن نمونه **به dev مهاجرت** می‌کند،
   نمونه‌ی جایگزینِ دست‌نخورده از همان توزیع می‌نشیند، و نمره‌ی test دوباره
   «تازه» می‌شود.
3. نمره‌ی test هر نسخه‌ی موتور **یک‌بار** گزارش و در CI قفل می‌شود.
4. برچسب‌زنیِ holdout **کور** انجام می‌شود: برچسب‌زن ابتدا بدونِ دیدنِ خروجیِ
   موتور می‌نویسد، سپس برگه‌ی تأیید (با فیلترِ سازگاریِ خانواده‌ای) می‌آید.

## ۳. حلقه‌ی «منتقدِ بی‌رحم» (هر نسخه)
چک‌لیستِ اجباری — با دیدِ منتقدِ وحشی، نه برای تأیید بلکه برای شکستن:
1. **درستی:** خروجیِ طلایی‌ها + پرتگاه‌ها (قیمت/دسته/ویژگی/نام/برند/چندمحصوله).
2. **پوششِ منفی:** «نباید»ها («شماره ۱۲»ِ بدون آرایش، حجم/ساعت = قیمت نشود،
   تله‌های «مامان/مداومه»).
3. **ضدِ بیش‌برازش:** `lexicon_audit` (کلیدِ مرده/تک‌نمونه‌ای) + مقایسه‌ی نمره‌ی
   dev با test (شکافِ زیاد = بوی بیش‌برازش).
4. **پایداری:** فازینگ (تستِ تصادفیِ قطعی) + ورودی‌های نامعتبر/خالی/فوق‌بلند.
5. **کالیبراسیون:** اعتمادِ بالا باید با خطایِ کمتر همراه باشد (گزارشِ `calibration`).
6. **سازگاریِ برچسب‌ها:** سپرِ خطای انسانی (تضادِ خانواده/واژه) = صفر.
7. **شفافیت:** هر ادعا Evidence داشته باشد؛ «استخراج‌شده ≠ تأییدشده».
8. **سقفِ بلندپروازانه:** اگر حتی یک «بهبودِ انجام‌نشده» به ذهن می‌رسد، هنوز
   قله فتح نشده — در roadmap ثبت و اجرا می‌شود.

## ۴. گیت‌ها
- **گیت‌های dev** (قفلِ رگرسیون در CI): قیمت ≥۰٫۹۹ · دسته ≥۰٫۹۴ · ویژگی ≥۰٫۸۵ ·
  بازیابیِ محصول ≥۰٫۹۵ · دقتِ تکه ≥۰٫۸۵ · نام ≥۰٫۹۰ · برند ≥۰٫۹۵ · فازینگ سبز ·
  سازگاریِ برچسب = صفر تضاد.
- **گیت‌های test** (به‌محضِ وجودِ holdout، خودکار فعال می‌شوند — `test_gold_test_split_gates_when_holdout_exists`):
  قیمت ≥۸۵٪ · دسته ≥۷۵٪ · ویژگی ≥۷۵٪ (حداقلِ قراردادِ فاز ۱؛ با بزرگ‌شدنِ
  holdout سخت‌تر می‌شود).

## ۵. وضعیتِ فعلی
- dev = ۶۴ نمونه (بچ ۱) · adversarial = ۲۸ · test = **خالی تا تمدیدِ Data API**
  (پس از تمدید: ۲۰–۳۰ نمونه از اکانت‌های جدید → مستقیم holdout).
- همه‌ی خروجی‌های `gold-score` شاملِ گزارشِ سازگاری/کالیبراسیون/واژگان است.
